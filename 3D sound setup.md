### 🎵 **System Overview (Very Minimal)**

You have a **Raspberry Pi 5** that acts as the central **music player + visualizer** — it plays:

- **Local audio files**
- **NTS radio streams**
- Possibly other inputs

It runs **ProjectM (with projectM-pulseaudio)** to generate **real-time visuals** synced to whatever audio is playing.

The Pi’s **HDMI output connects to your receiver** (**Marantz NR1510**), which:
- **Plays the audio in surround (5.1)** to your speakers
- **Passes the video signal out** to your **ON CPR 300 mini projector** for viewing on a screen or wall 
    This gives you immersive sound and visuals together.

Optionally, you can add **LED strips** (e.g., WS2812/NeoPixels) around the screen or space, driven by the Pi with software like **Hyperion** or custom code — so the LEDs **light in sync with the audio/visuals** for an even more immersive effect.

```
Raspberry Pi 5
	├─ plays music (local / NTS / others)
	├─ runs ProjectM visuals
	└─ outputs HDMI → Marantz AVR

Marantz AVR
	├─ plays 5.1 surround audio to speakers
    └─ outputs video to mini projector

Optional
	Raspberry Pi controls LED strips for synced lighting
```

### 🎧 **Key Points**

- The Pi handles both **audio playback and visualization**.
- The AVR takes the Pi’s HDMI signal and delivers **surround sound + video passthrough**.
- The projector displays the visuals generated by ProjectM.
- LED strips can be driven with software on the Pi (e.g., Hyperion) for lighting tied to audio/visual output.

# Speed

If you want **minimum latency** with projectM (audio → visuals), optimize these layers:

---

## 1️⃣ Audio path (most important)

**Avoid PulseAudio if possible. Use PipeWire or pure ALSA.**

- On Raspberry Pi: use **ALSA directly** if you can.
    
- Lower the **buffer size**:
    
    - 128 samples = very low latency
        
    - 64 samples = excellent (if stable)
        
- Use **48 kHz** sample rate (most HDMI setups run at 48k).
    

Smaller buffer = lower latency, but more CPU load.

---

## 2️⃣ Use direct audio capture

Best option:

- Feed projectM the **same audio stream** that goes to the AVR.
    
- Avoid:
    
    - HDMI audio re-capture
        
    - Bluetooth (adds huge latency)
        
    - Network audio
        

If using PipeWire:

- Connect projectM directly to the monitor node.
    
- Avoid resampling.
    

---

## 3️⃣ Graphics pipeline

On Raspberry Pi 5:

- Use **KMS / DRM fullscreen**
    
- Avoid running in a heavy desktop environment
    
- Disable compositing
    
- Run fullscreen, no window borders
    

If possible:

projectM --fullscreen --no-gui

The less the OS touches frames, the better.

---

## 4️⃣ Frame timing

- Set FPS to match display (usually 60 Hz)
    
- Disable VSync _only if_ it causes delay (test both)
    
- Avoid frame limiting below monitor refresh rate
    

---

## 5️⃣ CPU / GPU performance

- Set performance governor:
    

sudo cpufreq-set -g performance

- Ensure GPU memory split is sufficient (Pi config)
    

---

## 6️⃣ Absolute lowest latency architecture (best setup)

**Ideal chain:**

Music player  
→ ALSA (low buffer)  
→ Split stream  
→ HDMI (Marantz)  
→ projectM (same audio buffer tap)  
→ HDMI video

No Bluetooth  
No resampling  
No network audio

---

## What latency is realistic?

- 20–40 ms = very good
    
- <20 ms = excellent
    
- > 100 ms = something is wrong
